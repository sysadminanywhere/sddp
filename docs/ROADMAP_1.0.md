# SDDP — план до 1.0

Цель — спроектировать интеграцию в контуре разработчика, перенести snapshot в изолированный контур заказчика, собрать версионированный артефакт для заданного окружения и запустить его. Изменение контракта, маппинга или транспорта требует пересборки и выпуска артефакта. [Первоначальное ТЗ](https://github.com/sysadminanywhere/sddp/blob/dde5335ca4a0fac4bf6a36ef04d488b18bf7c55f/sddp_implementation_plan.md)

## Изолированная поставка

- [ ] Подготовить комплект с образами, зависимостями и инструкцией установки. Указать контрольные суммы и процедуру обновления и восстановления.

## Критерий 1.0

REST и Kafka проходят полный цикл на чистом изолированном стенде. Для обеих интеграций команда может воспроизвести установку, перенос проекта, сборку, запуск, обновление и восстановление по сохранённой документации. Поддержка дополнительных транспортов и форматов зависит от требований пилотов.
