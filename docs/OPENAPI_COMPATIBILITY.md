# Совместимость OpenAPI в SDDP

## Проверка на 0.2.0

21 ноября 2026 года проверили четыре публичных контракта через REST API SDDP с чистой PostgreSQL. Для каждой выборки использовали исходные операции и сохранили компоненты, на которые они ссылаются. YAML предварительно преобразовали в JSON. Проверка генерации включала создание REST-связи в DEV, повторный импорт с сохранением идентификатора и компиляцию Java 21. Запросы к сервисам поставщиков не выполнялись.

| Контракт | Операций в полном документе | Принято в выборке | Результат |
| --- | ---: | ---: | --- |
| [GitHub REST](https://github.com/github/rest-api-description/blob/main/descriptions/api.github.com/api.github.com.json), 1.1.4 | 1 281 | 0 из 36 | У всех проверенных операций Issues идентификаторы непригодны для имени метода Java. После замены только `operationId` у `GET /repos/{owner}/{repo}/issues` операция импортировалась, клиент сгенерировался и скомпилировался. |
| [Stripe](https://github.com/stripe/openapi/blob/master/latest/openapi.spec3.json), 2026-11-18.endive | 706 | 0 из 25 | У 13 операций Customers первым блокером оказалась сериализация параметров, у 12 — отсутствие схемы `application/json`. Например, создание клиента Stripe использует `application/x-www-form-urlencoded`. |
| [DigitalOcean](https://github.com/digitalocean/openapi), 2.0, официальный собранный YAML | 917 | 28 из 30 | Для списка и создания Droplets прошли импорт, повторный импорт, генерация и компиляция. Два предупреждения о неподдерживаемых HTTP-параметрах. |
| [GitLab REST](https://gitlab.com/gitlab-org/gitlab/-/blob/master/doc/api/openapi/openapi_v3.yaml), 19.7 | 1 870 | 4 из 36 | Для добавления задачи в список дел и чтения истории состояния прошли импорт, повторный импорт, генерация и компиляция. У 28 операций первым блокером стали нескалярные схемы параметров, у четырёх — дополнительные поля рядом с `$ref`. |

Во всех четырёх случаях предпросмотр полного документа вернул HTTP 400 с сообщением `Import supports at most 200 operations`. Выборки ограничили путями с префиксами `/repos/{owner}/{repo}/issues`, `/v1/customers`, `/v2/droplets` и `/api/v4/projects/{id}/issues` и глубиной до 6, 4, 5 и 7 сегментов соответственно. Знаменатели в таблице относятся к этим выборкам.

## План 0.3.0

1. [x] Выбор до 200 операций из полного документа до разворачивания схем с прежними ограничениями на размер запроса, глубину и объём разворачивания схем.
2. [x] Стабильные Java-имена для внешних `operationId` с сохранением уже допустимых имён и обработкой коллизий.
3. [x] Загрузка YAML с теми же проверками OpenAPI, что и для JSON.

## Повторная проверка на 0.3.0-SNAPSHOT

Предпросмотр открыл полные документы GitHub, Stripe, DigitalOcean и GitLab с исходным количеством операций из таблицы. DigitalOcean и GitLab загрузили в YAML. Для выбранных операций импорт, повторный импорт с теми же идентификаторами и компиляция Java 21 дали следующие результаты.

| Контракт | Проверенные операции | Результат |
| --- | --- | --- |
| GitHub REST | `GET /repos/{owner}/{repo}/issues` | Прошло с исходным `operationId` и автоматически преобразованным Java-именем. |
| DigitalOcean | `GET /v2/droplets`, `POST /v2/droplets` | Прошло с исходным YAML и с полным контрактом, преобразованным в JSON. |
| GitLab REST | `GET /api/v4/projects/{id}/issues/{eventable_id}/resource_state_events`, `POST /api/v4/projects/{id}/issues/{issue_iid}/todo` | Прошло без сокращения или конвертации исходного YAML. |
| Stripe | `GET /v1/customers`, `POST /v1/customers` | Предпросмотр показал ограничения сериализации и формата тела. Попытка импорта обеих операций вернула HTTP 400. |

Браузерный тест проверяет загрузку YAML с 202 операциями, сохранение выбора при фильтрации и возврате к списку, а также импорт только выбранных операций. Из ограничений выборок остаются form-urlencoded и `deepObject` для Stripe и нескалярные параметры и дополнительные поля рядом с `$ref` для части GitLab Issues.
